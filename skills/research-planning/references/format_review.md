# 《需求先进性审查报告》格式模板（类型码 SC）

## 适用场景

对单一科技需求/项目建议书做先进性、必要性及与公司在研布局重复性的审查，产出立项论证支撑材料。

## 输入

- 审查对象原文：调用方先经 `python tools/save_text.py <文件名.md> <内容>` 暂存至
  `kjgl研究谋划/inbox/`，本生成器以 `target=kjgl研究谋划/inbox/<文件名>` 读入。
- 文献证据：检索结果库（skills/research-planning/results/*.json），引用只许用编号文献表内的 [n]。
- 公司底数：`kjgl研究谋划/kjgl_base.json`（项目库+规划需求清单，自动读取）。

## 结构（章节标题与顺序固定）

```
<文档头（见通用规范）>
# 《<需求名称>》需求先进性审查报告
## 一、审查对象与审查依据
（一）审查对象        ← 概述需求背景、问题定义、研究内容构成（对照原文，不发挥）
（二）审查依据与方法  ← 写明项目/需求底数覆盖范围、检索通道与主题、检索日期、引用纪律
## 二、与公司现有科技项目及需求的关系
（一）项目库查重结果  ← 逐项比对；相关度较高者列 表1（列：现有任务|年度|研究侧重|与本需求的关系）
（二）衔接关系分析    ← 逐项说明互补/接力/边界划分建议
## 三、国内外研究前沿对标
（一）总体态势        ← 问题定义与国际前沿的同向性，带引用[n]
（二）研究内容1对标   ← 按被审需求的研究内容逐项一节：国际代表工作[n] + 差异化判断 + 需收窄之处
（三）研究内容2对标
……（逐项对应，节数随研究内容数增减）
（末节）行业应用对标  ← 电力行业是否已有同类布局、先发窗口判断
## 四、先进性结论与建议
（一）总体结论        ← 含 表2 分项先进性评定表（列：研究内容|国际前沿对应|评定|主要依据）；
                        评定用语限"国际同向并跑/并跑需收窄/行业领先/跟随"等档位，须有依据
（二）立项完善建议    ← 逐条可操作（创新点收窄、边界划分、指标基线、验证方法、合规依据）
## 参考文献
## 附：版本记录
```

## 质量要求

- 全文 3000–6000 字；引用文献 10 条以上且全部来自检索结果库。
- 查重对照必须落到 kjgl 具体项目编号/需求名称；确无重叠时明确写"不构成重复立项"并给依据。
- 每个研究内容的对标须同时给出"同向证据[n]"与"差异化/收窄建议"，禁止只写肯定结论。
