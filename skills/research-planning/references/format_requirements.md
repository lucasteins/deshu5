# 《下阶段需求清单》格式模板（类型码 XQ）

## 结构（固定）

```
<文档头（见通用规范）>
# 下阶段科技需求清单（<批次年份>）
## 一、编制说明
（一）编制依据        ← 引用 kjgl 现有项目/需求清单、综述文档编号
（二）清单结构说明    ← 演进类（R，对现有需求升级）与新拓类（N，新方向）的定义
## 二、需求清单汇总表    ← 表1：编号|需求名称|类型|技术领域|建议经费(万元)|周期|优先级|衔接项目/需求
## 三、演进类需求详述     ← 每条按"需求条目模板"填写
## 四、新拓类需求详述     ← 同上
## 五、入库与评审建议      ← 入库流程、评审要点、需前置准备的论证材料
## 附：版本记录
```

## 需求条目模板（每条需求严格按此字段顺序）

```
（<编号>）<需求名称>
1. 技术领域：
2. 类型与衔接：演进类/新拓类；衔接的现有项目编号或规划需求名称
3. 问题与必要性：   ← 三段式：现状与差距、不解决的后果、立项时机；前沿依据带引用[n]
4. 研究内容要点：   ← 3–5 个研究点，每个一句话概括+一句展开
5. 预期成果与考核指标： ← 指标须可量化（准确率/篇数/项数/金额）
6. 建议经费与周期：
7. 建议合作单位：
```

## 质量要求

- 汇总表先行，详述与汇总表条目一一对应、编号一致。
- "问题与必要性"中凡涉国际前沿的判断必须有引用支撑。
- 每条需求 400–800 字；清单总数 8–15 条为宜。
