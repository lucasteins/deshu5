# 素材提资字段映射规范（原始模板 → sc01_governance 标准数据）

- 版本：v1.1（2026-09-14）
- **地位：素材提资转换的唯一权威依据**。离线清洗（人工或 LLM）和在线转换（`modules/provision/provisioner.py`）都必须以本文档为准；规则要改先改本文档，provisioner 跟随。
- 配套：skill `material-import`（流程纪律）；实现 `modules/provision/provisioner.py`（路由 `modules/provision/routes.py`，`/api/provision/*`）。
- 库名：治理库 `sc01_governance`（生产档；仿真档 `fz01_governance`），业务库 `sc01`（生产档；仿真档 `fz01`）；2026-09-14 由 marketing_governance / marketing_40 迁移，档位见 `core/db_profile.py`。

## 一、通用约定

**溯源四类**（每个目标字段必须归类，写入 ingest_provenance.source_kind）：

| 类别 | 含义 | review_status |
|---|---|---|
| direct | 模板单元格原值直转，source_ref=单元格（如 S5!C3） | na |
| system | 系统推导（编码映射/SQL解析/执行回填/文本拼接），source_ref=推导方式 | na |
| llm | LLM 标注产物，source_ref=llm:模型名 | pending（默认待复核） |
| manual | 人工标注/复核改值 | confirmed（复核后） |

**幂等键**（重跑不产生重复行）：schema_table_docs=table_name、code_values=code_name、code_value_items=code_name+item_code、code_value_column_form=table_name+column_name+code_name、schema_relationship_docs=title、qa_pairs=question、sql_knowledge=name+description。

**冲突保护**：目标行已存在且值有差异 → 默认不覆盖，差异项（库内值 vs 模板值）进人工复核队列（manual/pending），confirm 后才覆盖。

## 二、S2-管理元数据 → schema_table_docs

| 模板列 | 目标字段 | 转换规则 | 溯源 |
|---|---|---|---|
| 表名 | table_name | 原值 | direct |
| 中文名 | table_comment | 原值 | direct |
| 数据行数 | row_count | 转整数 | direct |
| 所属域 | domain_l1 | 域中文名→编码（人员→Hr…客户→Cst…，映射表见 business_domains） | system |
| 二级业务分类 | domain_l2 | 解析"Cst02客户"→取编码 Cst02；为空→待 LLM 归类 | system / llm(空时) |
| 层级/负责人/数据时间范围/更新频率/来源系统 | doc_text 尾部追加 | 拼接到 doc_text：`表名：x，中文名：y，行数：r，字段数：c。` + 运营属性段 | system |
| （推导） | doc_text 主体 | `表名/中文名/行数/字段数` 标准句式 | system |
| （推导） | column_count | 该表在 schema_column_docs 的实际列数 | system |
| （常量） | domain_l3 | NULL（预留） | system |

校验：层级∈{DIM,DWD,DWS,ADS}（fail）；所属域∈10 域（fail）；二级分类∈business_domains（fail）；必填非空（fail）；表不在 sc01（warn，不阻断）。

## 三、S3-码值维度 → code_values + code_value_column_form

| 模板列 | 目标字段 | 转换规则 | 溯源 |
|---|---|---|---|
| code_name | code_values.code_name | 原值 | direct |
| 中文名 | code_values.code_cn_name | 原值 | direct |
| 数据类型 | code_values.data_type | 原值 | direct |
| 描述 | code_values.description | 原值 | direct |
| 所属域 | code_values.domain_l1 | 域中文名→编码（同 S2 规则）；为空→Cst | system |
| （推导） | domain_l2 | NULL（码值域不打二级标签，域级聚合用） | system |
| 编码列名 | code_value_column_form.column_name + form | 配对形态判定：BOTH→'混合'、CODE ONLY→'编码'、DESC ONLY→'名称'；table_name 固定 'ANY'（模板不给表名） | system |
| 描述列名 | 同上（描述列一行） | 同上 | system |

**码值交叉校核（关键，2026-08-20 事故教训）**：模板 code_name 库内已存在 → 中文名/类型/描述逐字段比对，差异 warn 不阻断；模板明细 code_name+item_code 已存在但 item_name 不同 → **fail 级映射冲突，阻断直接转换，强制人工复核**。码值治理判定口径归口 skill `code-value-governance`。

| 模板列 | 目标字段 | 转换规则 | 溯源 |
|---|---|---|---|
| code_name | code_name | 原值（必须 ⊆ S3 维度，否则 fail） | direct |
| item_code | item_code | 原值字符串化（保前导零） | direct |
| item_name | item_name | 原值 | direct |

## 五、S4-表关联关系 → schema_relationship_docs

| 模板列 | 目标字段 | 转换规则 | 溯源 |
|---|---|---|---|
| 源表+目标表 | title | 组装 `源表 → 目标表` | system |
| 源表+目标表 | path | JSON 数组 `[源表, 目标表]` | system |
| 源列+目标列 | join_conditions | JSON 数组 `["源表.源列 = 目标表.目标列"]` | direct（列名原值）/system（组装） |
| 来源 | business_scenarios | JSON 数组 `["来源值"]`（DDL-FK/元仓血缘/人工梳理） | direct |
| （推导） | doc_text | `表关联路径：{title}\nJOIN 条件：\n  - {jc}\n适用业务场景：{来源}` | system |

校验：源表/源列/目标表/目标列在 sc01 information_schema 存在（不存在 fail——如 `dwd_cst_rcvbl_acct.cust_no` 这类幻影列要拦下）。

## 六、S5-问答对素材 → qa_pairs

| 模板列 | 目标字段 | 转换规则 | 溯源 |
|---|---|---|---|
| 自然语言问题 | question | 原值（去重键） | direct |
| 标准SQL | standard_sql | 原值；入库前 probe 执行（sc01），失败行 fail 阻断 | direct |
| 是否可用 | is_usable | 1→1、0→0、空→1 | direct |
| 来源（选填） | source | 空→'素材提资' | direct |
| （推导） | objects_involved | 从 standard_sql 提取 FROM/JOIN 表名 JSON | system |
| （推导） | answer | sc01 执行回填（COUNT+LIMIT5 样例 JSON） | system |
| （推导） | domain_l1/domain_l2 | 按 objects_involved 涉及表在 schema_table_docs 的标签取首个非空 | system |
| （推导） | generation_method | 固定 '素材提资'；ingest_time=当前时间 | system |
| 维护人 | （provenance 记录，qa_pairs 无此列） | 空缺 → manual/pending 进复核队列 | manual |
| （LLM 标注） | difficulty | 基础题/进阶题/挑战题（LLM 判定，规则：单表单条件=基础、多表/聚合=进阶、对比/占比/多步=挑战） | llm |
| （LLM 标注） | tags | 从 SQL 结构提取（单表查询/条件过滤/JOIN/聚合统计/分组/排序/TOP-N/时间趋势/对比分析/占比分析/极值查询） | llm |
| （LLM 标注） | explanation | 句式：`该SQL用于回答'{问题}'，采用{tags}方式，涉及表：{objects_involved}。` | llm |

## 七、S6-业务规则 → sql_knowledge

| 模板列 | 目标字段 | 转换规则 | 溯源 |
|---|---|---|---|
| 规则描述 | description | 原值 | direct |
| 正例SQL+反例SQL | sql_rule | 拼接 `正例SQL：\n{pos}\n反例SQL：\n{neg}`（**必须带前缀**：裸 SELECT 会被内容自证判为模板行） | direct |
| （常量） | name | 固定 'custom_rule'（多条时加序号 custom_rule#2） | system |
| （LLM 标注） | trigger_words | 从规则描述抽取业务关键词 JSON 数组 | llm |
| （推导） | sql_tables | 从正例 SQL 提取表名 JSON | system |

**注意**：若规则要进直出/注入通道，需另配 sql_expr/sql_filter 片段（见 sql_knowledge 现有口径规则），本模板默认只入知识库不参与直出。

## 八、LLM 离线转换指引（给执行清洗的 LLM）

1. 先读本规范全文 + skill `material-import` + 本 skill 目录《业务分类框架_SGCIM4.5.md》（域编码映射）。
2. 产出物是**离线标准数据文件**（INSERT SQL 或 JSONL，按目标表分文件），每个字段带溯源标注（direct/system/llm/manual + 来源）。
3. 必须执行的检查：本文档各节的校验规则 + 码值交叉校核（§三）+ 幂等键冲突检测。
4. 拿不准的一律标 manual/pending，不要猜——**错标比空着更贵**（cust_cls:03 事故）。
5. 产出后由人工复核 → 经「素材提资」页面或 provisioner 导入生产库。
